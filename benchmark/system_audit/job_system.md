# Durable local extraction jobs

The normal Streamlit uploaded-PDF path now publishes the PDF as an immutable content-addressed artifact before it creates a job or parses the source. The source record contains hash-derived `source_id`, SHA-256, original filename as metadata, media type, byte size, timestamp, and logical artifact reference. Equal bytes share one source artifact; each request gets a new job/run ID. Neither source identity nor job identity is based on a local absolute path. Publication uses a temporary file, flush/fsync, then create-only hard-link publication. A publication error leaves no RUNNING job. The normal UI then runs the job synchronously and automatically archives the validated result; the legacy Save action is an idempotent no-op for that record.

The `PENDING` event stores the validated source record and a non-secret execution snapshot: requested domain, extractor/schema/prompt identifiers, exact primary and fallback model IDs, provider mode, OCR/search/supplementary flags, and source identity. A resume overwrites runtime pipeline options with this snapshot, not current defaults. The snapshot does not preserve credentials; offline replay supplies a local placeholder key solely for extractor construction, and the gateway observer intercepts every generation call before SDK transmission. Changes to application code, prompt text, OCR installation, sidecar data, or external search results can make deterministic replay differ; request-hash checks then fail closed. The snapshot's `repository-current` prompt marker is not a content hash, so replay is only supported against the same compatible repository revision.

The live state path is `PENDING → RUNNING → WAITING_PROVIDER → VALIDATING → ARCHIVING → SUCCEEDED`. `FAILED` and `CANCELLED` remain terminal. `RECONCILIATION_REQUIRED` is a distinct terminal hold, not failure or a retry queue. Immediately before each Gemini gateway transmission, the job journal fsyncs an attempt entry with attempt ID/number, job/run IDs, provider, exact model, phase, request hash, source artifact reference, and intent timestamp. On return, raw response text is immutably published and referenced before parsing/validation; a provider exception is recorded by normalized class. A crash after intent without a durable outcome cannot prove whether the remote provider received or answered the request. On restart, that job is durably moved to `RECONCILIATION_REQUIRED` under its local execution lock, and no automatic provider retry is made. This is not exactly-once delivery.

| Durable state | Automatic action |
| --- | --- |
| PENDING | Verify source, then start. |
| RUNNING, before external intent | Rebuild source context and continue. |
| WAITING_PROVIDER, no intent | Continue from source under local lock. |
| WAITING_PROVIDER, latest intent without outcome | Mark RECONCILIATION_REQUIRED; no provider call. |
| WAITING_PROVIDER/VALIDATING, raw persisted | Rebuild and replay stored responses through the pipeline with request-hash/model/phase checks; no network call. |
| VALIDATING, validated artifact present | Move to ARCHIVING and finalize. |
| ARCHIVING | Load immutable validated archive and finish idempotently. |
| SUCCEEDED | Return archived record; no new work. |
| FAILED/CANCELLED/RECONCILIATION_REQUIRED | Operator review only. |

Offline replay requires every replayed provider phase to have a stored raw response; a prior failed provider attempt followed by fallback is not replayed automatically. A request mismatch, missing raw phase, or changed prompt fails closed without a network call. It may require future operator-controlled recovery. OCR can be environmentally nondeterministic and produce a prompt-hash mismatch. The generic `JobStore.resume_offline()` callback path remains available for deterministic callers.

## Operator recovery

The developer System audit Jobs tab offers only state-scoped **Resume safe job** and reconciliation decisions when `SYNTHEX_OPERATOR_ACTIONS_ENABLED=true`; otherwise it stays read-only. The API exposes `/v1/jobs/{job_id}/resume`, `/reconcile`, and `/abandon`, but mutations are disabled by default; set `SYNTHEX_OPERATOR_API_ENABLED=true` only behind a trusted operator boundary. No operator identity/authentication system exists, so the audit records `local_operator`. Each decision is a versioned, fsynced job event with action ID, type, timestamp, prior/resulting state, reason category, and optional artifact reference. Repeating an identical action ID is a no-op; conflicting reuse is rejected. A resume action is journaled before execution. If execution does not begin afterward, a new explicit action ID is needed; the safe state remains inspectable.

Unknown outcomes stay in `RECONCILIATION_REQUIRED`. Confirmed no result marks the uncertain provider/search action as confirmed missing and only makes a **later explicit resume** eligible to issue a new attempt; reconciliation itself never transmits. A recovered result must already exist in the immutable `raw` or `search` artifact store, pass checksum loading, and match the selected action's request hash, source identity, and provider model where relevant. That identity association is an operator assertion; the local artifact checksum cannot prove what a remote service actually received. Recovery then resumes locally from the persisted response. Abandon moves to terminal `CANCELLED`. There is no generic retry action, and `FAILED`/`SUCCEEDED` remain ineligible.

## Search action journal

The job-scoped Serper observer records search intent (action/run/job/source IDs, service, operation, attempt, normalized query hash, timestamp) before network transmission. HTTP response bytes are published immutably with temp-write/fsync/create-only hard-link and SHA-256 before JSON parsing or enrichment; a confirmed HTTP error is recorded by normalized class. Network exceptions/timeouts after intent remain uncertain. A cache hit is also journaled with its bytes and original cache-hit provenance before parsing, so replay does not depend on mutable cache state. A manually recovered artifact has unknown original cache-hit provenance. On restart, intent without outcome moves the job to reconciliation without a second search. A persisted response is replayed in query order with hash and checksum checks; query drift fails closed. New searches after provider replay require an explicit safe operator resume. Provider journaling remains compatible and separate. Standalone discovery and direct pipeline/CLI calls still use their existing synchronous paths and are not covered by the job journal. Local Serper usage counters may differ on replay because they are not a durable job snapshot; they are operational metadata, not scientific evidence.

One local thread/process owns a job at a time through a nonblocking OS file lock keyed by job ID, plus a process-local thread lock. An abandoned sidecar file does not retain ownership after process death. The journal and archive use separate local-process locks, append+fsync, and strict corrupt-tail handling. Archive identity is bound before append; replayed finalization accepts identical content and refuses conflicting same-ID content. Live jobs get job-scoped archive IDs so two independent requests for the same source do not collide. The job journal, source store, and archive store do not form a single transaction; idempotent finalization handles the cross-file crash window.

Supported: one host, multiple local threads/processes sharing one filesystem. Not supported: distributed worker coordination, multi-host leases, automatic reconciliation, automatic provider retries, exactly-once external delivery, and live resume after incompatible code/prompt changes. Direct CLI calls to `SynthexExtractionPipeline.extract_pdf` / `extract_text`, benchmark runners, and external callers not using `LiveExtractionService` remain synchronous legacy paths. There is no separate API extraction POST route in this repository; read-only `/v1/system/jobs` and `/v1/system/jobs/{job_id}` project safe job metadata. The Streamlit extraction page also shows a read-only durable job table. Neither view returns credentials, prompts, raw response bodies, or local source paths.
